# 018 — Grab and manipulate physics objects with 6DOF hands

## Goal

Allow tracked hands to pick up, carry, rotate, release and throw eligible game physics objects. Depends on #015/#016. Roadmap stage 6.

## Tasks

- [x] Fix native hand proxy self-obstruction: room-scale body queries must ignore owned arm shapes, and vehicle entry must not be blocked by them. Recheck room movement with hands in front, wall blocking, car entry/exit and ordinary prop/door contact.

- [x] Add tracked hand/forearm contact with existing dynamic props before grabbing using collision shapes registered with native physics, rather than manual object impulses. Cover palms/fingertips and forearms; verify slow contact, blocking and pushing against chairs and small props.
- [x] Trace native collision-shape/instance creation, simulation update, collision filtering and destruction. Prototype tracked targets driving physics hands, with the visible IK following collision-resolved hands. Preserve the existing body collider and exclude self/held-weapon contacts; clean up on tracking loss, owner replacement and VR shutdown.
- [x] Identify eligible dynamic objects and game physics ownership; define reach, grip detection and object mass/size limits.
- [x] Support native NPC articulated physics: acquire active ragdolls and wake settled corpses; preserve registered mass/native joints. Verify sustained dead-body holding, release and reacquisition after settling.
- [x] Verify two-handed ragdoll manipulation.
- [ ] Broaden NPC lifecycle coverage: living recovery, corpse deletion/despawn and tracking loss.
- [x] Support one- and two-hand, strength-limited manipulation of generic dynamic props without a model whitelist. Start with small props/chairs; retain a path for tables, detached vehicle parts and stabilizing heavier vehicles such as motorbikes.
- [x] Allow grab/pull to open unlocked car doors through their native hinge/fragment behavior; preserve locks and scripted ownership.
- [x] Implement a physical grab constraint or equivalent verified interaction that follows the hand while respecting world collision.
- [ ] Derive release/throw velocity from valid tracked motion; handle two hands, tracking loss and object deletion cleanly.
- [ ] Test picking up, carrying, rotating, dropping and throwing several objects, including contact with scenery and flat-screen regression.

## Done when

Eligible objects can be manipulated in six degrees of freedom and released with coherent physics, without unstable constraints, duplicated objects or retained grabs after tracking loss.

## Unverified compatibility follow-up

Native carry/pickup recognition differs from our physical grip, but no mission or progression requirement has been identified. Preserve the native analysis for future use; defer implementing an adapter until a specific mission/script demonstrates the need. This is not an acceptance gate for #018. Money/weapon reward pickups remain tracked separately in #025.
