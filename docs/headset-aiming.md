# Interim headset-directed aiming

Accepted2026-10-04: the user confirms the requested normal-gun shot/head yaw-pitch/right-stick/controller lock-on test works and accepts the combined implemented gameplay route. #014 is closed; scopes/special weapons remain unverified in #016. The final VR-disabled run had zero aim overrides and no lock-on suppression, and the user confirmed flat-screen gameplay. Historical prototype notes below describe the investigation before acceptance.

Issue #014 targets ordinary on-foot aiming before controller weapon poses in #016. Enable `ExperimentalHeadsetAim=1` with the first-person stereo path; the distributed default is off. Baseline: GTA IV CE1.2.0.59 x86, SteamVR2.17.10, system D3D9Ex.

Ghidra `CCamAimWeapon` vtable at `00E9B98C` owns update `00A26BC0`, a thiscall with no stack arguments returning AL. The update's two orientation sites at `00A282B8` and `00A2874B` store pitch from XMM0 into ESP, with yaw already at ESP+4, then invoke `00C3E740` with ECX=cam+10. Assembly confirms RET8 and the helper `008D4E60` creates forward `(-sin(yaw)*cos(pitch), cos(yaw)*cos(pitch), sin(pitch))`; `00C3E790` builds right/forward/up matrix rows. Camera+204 is the target ped; +218/+21C hold pitch/yaw. These are Ghidra addresses, base00400000; signatures resolve each live image without assuming its relocated base.

The guarded prototype replaces pitch/yaw immediately before these native basis builds, after ordinary input/target adjustment. It updates the angle fields used by subsequent character aiming and publishes the headset midpoint matrix after the original camera update. Native matrix rows are right/forward/up, while the viewport rows are right/up/back. Fire controls, ammunition, damage and weapon spread remain engine-owned. This is a gameplay camera integration candidate; callback counts do not prove actual projectile direction.

Fresh focused first-person samples must belong to the same local on-foot ped and be no older than250ms. Pause, vehicle and animated-action states suspend the override. Near-vertical gaze retains the previous yaw. `DISABLE_PLAYER_LOCKON` handler `00BB33C0` resolves player ped and changes ped+264 bit00800000. The simulation callback preserves that bit before suppressing lock-on, restores it when inactive for the same ped, and drops stale ownership when the player changes. No prior ped pointer is followed after ownership changes. Simultaneous script ownership of the same flag remains a limitation.
